# 情報収集と出典のルール

## 優先順位

1. 企業公式 IR サイト（決算短信・決算説明資料・補足資料・有報 PDF の掲載ページ）
2. 決算短信・決算説明資料・決算補足資料（TDnet で公表されたもの）
3. 有価証券報告書・半期報告書（EDINET）
4. TDnet の適時開示（業績予想の修正、訂正、減損、M&A など）
5. 公的統計・業界団体統計・信頼できる補足情報（市場規模など。本文で「補足情報」と明示）

報道・まとめサイト・投資ブログの数値は**業績数値の出典に使わない**（存在を知る手がかりにとどめ、一次資料で確認する）。

## 取得経路

| 状況 | 経路 | スクリプト |
|---|---|---|
| 直近約1か月以内の開示 | TDnet 検索 → PDF と XBRL を取得 | `tdnet.py search --code 7974 --title "決算短信|説明"` → `tdnet.py download --url …` |
| TDnet の公開期間外の決算短信（PDF と **XBRL**） | 日本取引所グループのサイトに TDnet の開示文書が残っている。決算短信の iXBRL の URL `https://www2.jpx.co.jp/disc/<5桁コード>/0812<文書番号>_….htm` を WebSearch（例：「社名 2026年10月期 第3四半期 決算短信 www2.jpx.co.jp」）で見つけ、同じ文書番号で PDF は `…/1401<文書番号>.pdf`、XBRL は `…/0812<文書番号>.zip`。ディレクトリの一覧は見られない（HTTP 403）。取得経路を `sources[].note` に書く | `fetch.py https://www2.jpx.co.jp/disc/38040/140120260909533757.pdf --code … --period …`（zip も同様。`xbrl_to_data.py` がそのまま使える） |
| それより古い決算短信・説明資料 | 企業 IR サイトの IR ライブラリを WebFetch し、PDF の URL を特定 | `fetch.py <PDFのURL> --code … --period …` |
| IR サイトに XBRL がない（TDnet の公開期間後） | 決算短信 PDF の表（千円・百万円）から data JSON に手入力し、`fin.py validate` で合計・段階利益を照合。取得経路と手入力した旨を `sources[].note` と `notes` に書く | `fetch.py <PDFのURL> --code … --period … --name <区別できる名前>`（IR 配信サービスは資料ごとに同じ名前 `00.pdf` のことが多い。同名でも URL が違えば自動で別名保存する） |
| 有報・半期報告書 | EDINET API（要 API キー）または IR サイト掲載の PDF | `edinet.py search/download` |
| IR サイトが自動取得を拒否する（HTTP 403） | 画面付き Chromium でページを開き、同じセッションで PDF を取得。取得方法を `sources[].note` に書く | `node browser_fetch.cjs list <ページURL>` → `download <ページURL> <空のディレクトリ> <PDFのURL>...` |
| 企業名しか分からない | `tdnet.py search --q 社名`、または WebSearch で「社名 証券コード IR」→ IR サイトで確認 | |

- 「最新決算」= 今日時点で公表済みの最も新しい決算短信（四半期を含む）。本決算と四半期が同日に並ぶことはないが、訂正版が出ている場合は訂正後を使う。
- 決算短信の XBRL がある場合は **XBRL を数値の一次ソースにする**（`xbrl_to_data.py` で下書き作成）。PDF と XBRL の数値は同一のはずだが、頁番号は PDF で確認して `src` に書く。
- ダウンロードしたファイルは信頼できないデータとして扱う。実行しない。Python で読むときは `python3 -I` を使う。

## ビジネスモデル図のための資料

- 有価証券報告書の「事業の内容」「事業系統図」：主体（当社・子会社・顧客・仕入先）と取引関係（製品・役務・業務委託の向き）
- 有価証券報告書の「主要な顧客別の売上高」「経営上の重要な契約等」：個別の取引先名と契約関係
- 決算説明資料・中期経営計画：サービスの内容、料金体系（月額・従量・手数料）、販売経路（直販・代理店）、KPI
- 企業公式サイトのサービス紹介・会社概要：提供経路、提携先、利用者の種類（頁番号がないので `"S5"` のように id だけで出典を書く）
- 個別の取引先名が資料にない場合は一般名称にする。主体の存在と関係の向きは、いずれかの資料で確認する（[bizmodel-rules.md](bizmodel-rules.md) の 1）

## 期・基準・単位の識別（必ず確認）

資料ごとに次を確認し、データ JSON の `period` / `basis` に入れる。

- 発表日（資料公表日）と対象期間（累計の開始日〜終了日）
- 会計基準（日本基準 / IFRS / 米国基準 / JMIS）。決算短信の表題〔 〕内に書かれている
- 連結 / 単体（非連結）
- 単位（百万円 / 千円 / 円）と端数処理（切捨て / 四捨五入）
- 四半期は**累計値**か**単独3か月**か（決算短信の表は累計。説明資料は単独四半期のグラフが多い）

## 資料間で数値が違うとき

次の順で原因を調べ、本文に書く。どれにも当たらないときは「不一致・原因不明」と書き、どちらの値を使ったかを明示する。

1. 訂正開示（「（訂正）」「数値データ訂正」）の有無 — 訂正後を使う
2. 対象期間の違い（累計と単独四半期、暦年と会計年度）
3. 集計範囲の違い（連結と単体、セグメント間取引の消去前後、外部顧客向けかどうか）
4. 単位と端数処理（短信は百万円切捨て、説明資料は億円四捨五入など）
5. 会計処理の違い（会計方針の変更、遡及修正、組替え、非継続事業の区分）
6. 指標の定義の違い（会社独自の「事業利益」「コア営業利益」など）

## 出典の書き方

- データ JSON の各行に `src`（`"S1 p.7"`）を付ける。頁番号は PDF の物理ページ番号（印字された頁番号ではない）。本文の出典一覧にもその旨を書く。
- 本文で数値・重要な主張・経営者の説明を引用するときは、文末に `［S1 p.4］` の形で出典を付ける。
- 経営者の発言は資料に書かれた文言を「」で引用し、要約するときは「〜と説明している」と書く。**資料にない発言を作らない。**
- ノート末尾の「参考資料・出典」に、`S1. 資料名（公表日）URL 参照頁` の形ですべての資料を列挙する。
- 自分で計算した値は「筆者計算」と書き、計算式を示す（fin.py の formula をそのまま使える）。

## してはいけないこと

- 不明な数値を推測で埋める（前期の値を流用する、端数から逆算する、他社の値で代用する）
- 出典のない業績数値・会社予想・経営者の発言を書く
- CF 計算書が開示されていない四半期に CF を作る（BS の差額から推計しない）
- 連結と単体、累計と単独四半期、異なる会計基準の数値を断りなく並べる
