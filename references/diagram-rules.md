# 財務三表の図のルール

図は `diagrams.py build` が数値から生成する。**手で図形を描いたり、画像生成 AI で代替したりしない。**
draw.io の編集用ファイル（.drawio）と、Obsidian で表示する SVG（`--theme light` で白背景に固定、図のデータを埋め込み済み）を出力する。

## 共通

- 白背景・日本語ラベル・金額と単位・対象期間を必ず表示（見出しと副題に自動で入る）
- 配色：収益・資産＝青緑系、費用・負債＝オレンジ系（有利子負債は濃いオレンジ）、利益・純資産＝緑系、
  損失・マイナス＝赤の破線枠と赤字（「△」表記）、現金残高＝青
- 高さ（面積）は金額に比例。1つのパネルの中では縮尺は1つ。PL の①と②のように縮尺が違う場合は図中に倍率を書く
- 表示単位：売上高（なければ総資産）が100億円以上なら億円、未満なら百万円（設定 `display_unit` で固定可）。換算は四捨五入で、100億円未満は小数1桁
- 図幅 820px。Obsidian では `![[…svg|760]]` で埋め込む（設定 `embed_width`）
- 小さいブロックのラベルは外側に出して引き出し線でつなぐ。重ならないよう縦に積む

## PL 図（参考画像1のイメージ）

- ① 収益から最初の段階利益（通常は営業利益、銀行は経常利益など＝`pl.split_after`）まで：
  左列＝費用（売上原価、販管費、その他の費用）＋利益、右列＝収益（売上高、その他の収益）。左右の高さは同じ
- 売上高を100%とした構成比を各ブロックに表示
- 売上総利益のような中間の段階利益は、右側の括弧で範囲を示す（収益がすべて上に並ぶ場合だけ。成立しない場合は描かない）
- **赤字**：利益ブロックを作らず、損失額を右列の下に赤い破線枠で置いて左右をそろえる（損失を正の積み上げとして扱わない）
- ② 段階利益から最終利益まで：ウォーターフォール。営業外損益・特別損益・金融損益・持分法・税金・非支配株主を省略しない。
  合計（段階利益）は緑（マイナスなら赤破線）、プラスの項目は青緑で上向き、マイナスの項目はオレンジで下向き
- 営業段階の収益・費用に負の値があると図を作らない（kind と符号の誤りの可能性があるため）

## BS 図（参考画像2のイメージ）

- 左＝資産、右＝負債・純資産。左右の総額を同じ高さにする
- グループ（流動資産・固定資産・流動負債・固定負債・純資産）ごとに括弧と合計・構成比を表示
- 総資産の2.5%未満の科目と、貸倒引当金などのマイナス科目は「その他」に集約（`highlight: true` の科目は小さくても残す）。集約の内訳は脚注に書く
- 重要科目（`highlight: true`）は太枠。有利子負債は濃いオレンジと「（有利子）」表記
- **債務超過**：純資産の不足額を資産側の下に赤い破線枠で置き、左右の高さをそろえる。右側の合計の下に「うち純資産合計 △…＝債務超過」を表示
- 純資産の構成要素にマイナスがある場合（その他の包括利益累計額がマイナスなど）は、純資産を1つのブロックにまとめ、内訳を脚注に書く

## CF 図（参考画像3のイメージ）

- 期首残高 → 営業CF → 投資CF → 財務CF → 為替換算差額 → その他の増減（連結範囲の変更など） → 期末残高 のウォーターフォール
- 増加は緑で上向き、減少は赤の破線で下向き、残高は青
- 営業CF と投資CF の上に括弧でフリーキャッシュフロー（定義：営業CF＋投資CF）を表示
- 脚注で「期首＋各増減＝計算上の期末」と「開示された期末残高」との差を表示（0 または丸め誤差であること）
- 期首と期末は同じ定義（現金及び現金同等物）を使う
- CF 未開示の期は図を作らない（スクリプトが `skipped` に理由を出す）

## セグメント図（補助図 SEG）

- セグメントが2つ以上（`segments`）、または単一セグメントで `revenue_breakdown` が2つ以上あるときだけ作る
- 円グラフ2つ：左＝売上高の構成、右＝セグメント利益の構成。中心角（面積）は金額に比例し、12時の位置から時計回りに data の順で並べる
- 色はセグメントを表し、左右の円で同じ色は同じセグメント（「その他」は灰色）。各扇形に名前と構成比を引き出し線で付ける
- 赤字（または利益ゼロ）のセグメントは構成比を表せないため利益の円に含めず、脚注にセグメント名と金額を書く。利益の円の構成比の分母は黒字セグメントの利益の合計（本文で小計に対する比率を使う場合は、分母の違いを書く）
- 黒字のセグメントが1つ以下なら利益の円は作らない（100%の円になり情報がないため）。売上高の円と表だけにする
- 円の下に表（売上高・構成比・セグメント利益・構成比・利益率）を置く。赤字は赤字で表示
- 利益は調整額控除前のため、合計は連結の営業利益と一致しないことを脚注に書く
- 売上規模と利益貢献の違い（売上は大きいが利益は小さい事業など）を本文の「ビジネスモデル」で説明するときに使う

## 検証（build の結果に含まれる）

`diagrams.py build` は書き出し後に次を確認し、1つでも失敗すると `ok: false` を返す。

1. 金額ブロックの高さ（横棒は幅）＝ |金額| × 縮尺（誤差 0.6px 以内）。各ブロックに `fra_value` / `fra_scale` 属性を保存している
   円グラフの扇形は、中心角の割合＝金額 ÷ 円の合計（誤差 3×10⁻⁶ 以内）、扇形が隙間なく 0〜1 周を覆うこと、正円であること（`fra_value` / `fra_total` / `fra_pie` 属性）
2. 図に置いたすべての文字列が SVG に出力されている（文字切れ・欠落がない）
3. 文字列同士が重ならない（推定外接矩形）、図形に収まる、キャンバスからはみ出さない、括弧・軸の線と重ならない
4. SVG にダークモード用の配色が入っていない（白背景で固定）

ok が false のときの直し方:

- 外側ラベルが多すぎる → `_prepare_side` の集約閾値（`min_share`）を上げる、または科目を data JSON 側でまとめる
- 長い科目名が重なる → data JSON の `label` は変えず、`short_name` 等ではなく図側の折り返しに任せる。直らなければスクリプトの幅（CW, LANE）を調整
- 目視確認：`--png` を付けると同じ場所に PNG を出す。Read で開いて確認する（PNG はノートに埋め込まない）
