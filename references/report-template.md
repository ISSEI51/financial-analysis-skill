# ノートのテンプレート

ノートは `obsidian.py upsert` で書き込む。**本文（body）には fra:auto マーカーの内側に入る部分だけを書く。**
ナビゲーション（fra:nav）とメモ欄はスクリプトが付ける。

## 1. 決算ノートの frontmatter（fm.json）

```json
{
  "会社名": "任天堂株式会社",
  "証券コード": "7974",
  "業種": "その他製品",
  "決算期": "2027年3月期 第2四半期",
  "対象期間": "2026-04-01〜2026-09-30（6か月累計）",
  "資料公表日": "2026-11-05",
  "分析日": "2026-11-18",
  "会計基準": "日本基準",
  "連結・単体": "連結",
  "企業概要": "[[決算分析/任天堂(7974)/企業概要]]",
  "tags": ["決算分析", "決算分析/7974", "決算/第2四半期", "会計基準/日本基準"],
  "fra_type": "period_report",
  "fra_period": "2027年3月期_第2四半期",
  "fra_data": "決算分析/任天堂(7974)/data/2027年3月期_第2四半期.json",
  "fra_sample": "false"
}
```

## 2. 決算ノートの本文（body.md）

見出しの文言のうち、`check_report.py` が必須とするもの：
「3分でわかる決算概要」「ビジネスモデル」「損益計算書」「貸借対照表」「キャッシュ・フロー」「7つの観点」
「今回の決算からわかったこと」「まだ判断できないこと」「次回決算で確認すべき指標」「参考資料・出典」。
業種や情報量に応じて節を足したり、内容を短くしたりしてよい（見出しは残す）。

````markdown
# {会社名}（{コード}）{決算期}

> [!info] この資料について
> - 対象：{決算期}（{対象期間}）、{連結/単体}・{会計基準}
> - 主な資料：{S1 の資料名}（{公表日}）ほか（末尾の出典一覧）
> - 単位：表は原資料の単位（{百万円}・{端数処理}）。本文の「億円」は開示値を換算して四捨五入した値のため、会社資料の億円表記（切捨ての場合）と1億円ずれることがある
> - 出典の頁番号は PDF の頁番号（資料に印字された頁番号とは異なる場合がある）
> - 「筆者計算」と書いた値は開示値から計算した値で、会社の開示値ではない
> - 学習のための資料であり、投資判断を勧めるものではない
````

## 3. 企業概要ノートの本文（overview body）

企業概要は会社ごとに1つ。決算を追加するたびに内容を見直して upsert する（ビジネスモデルの理解が更新されたら書き換える）。
決算ファイル一覧と主要数値の推移は `obsidian.py relink` が fra:list ブロックに自動生成する。

````markdown
## 会社の基本情報

| 項目 | 内容 |
|---|---|
| 商号 | {公式商号} |
| 証券コード | {コード}（{上場市場}） |
| 業種 | {東証33業種} |
| 決算期末 | {3月末} |
| 会計基準 | {日本基準}（{連結}） |
| IR サイト | {URL} |

## 事業の概要とビジネスモデル

（何を・誰に・どう売り、どこで利益を生むか。最新の決算ノートへのリンク）

## 強みと主なリスク（現時点の理解）

## 現時点の主な論点

（直近の決算ノートの「次回決算で確認すべき指標」と、継続して追っている論点）
````

- 決算ごとの分析日・ノートへのリンク・主要数値の推移は `relink` が fra:list に自動で作るので、本文に履歴を書かない。
- **更新するときは既存の企業概要を Read してから**、その内容（ビジネスモデルの理解、強み・リスク）を引き継いで書き直す。
  他の決算期の分析で書かれた内容を、根拠なく削らない。
